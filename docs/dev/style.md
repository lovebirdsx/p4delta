# 注释与输出文案

**注释一律中文**，技术标识符原样：`p4 fstat`、`P4CHARSET`、`GetCommandLineW`、`head_rev` 这些每个都能拿去搜 Perforce 或 Windows 的文档，译成中文反而搜不到。中文标点，中文引语用 `「」`，标识符与**引文**用反引号——引文要能原样贴进搜索框，换成引号或译成中文就搜不到了。

三类保留英文原文：

1. **引文**——p4 文档/帮助页的原句（如 `This flag doesn't affect open files.`）与 p4 的报错原文（如 `Argument parsing ambiguity.`）。照抄，中文解释附在后面；
2. **标识符、命令、环境变量名**，见上；
3. **格式规格里的字节名与字段名**——`src/p4/marshal.rs` 的布局说明用中文写，`'s'`、`'0'`、`i32` 这些原样。

**clap 字段上的 `///` 是另一回事**：它们不是注释，是 `--help` 的正文，改它等于改用户可见的输出。仓库现在统一用中文（`src/cli.rs` 一度中英混排），但今后动它要当**输出改动**对待——单独提交、提交信息里写明，别当注释顺手改。

**写什么**：写「为什么」与「为什么不能反过来」。这个仓库里注释的价值集中在实测过的反直觉行为——p4 在 Windows 上解析两遍命令行、`?` 能匹配零个字符、符号链接的摘要按正斜杠算、`p4 sync -f` 对着被别的进程占用的文件会先打 `deleted as` 再失败。这些约束一旦在重构里丢掉，后来者会顺着直觉把它们改回去。

**不写什么**：代码已经说清的（`// 建立路径索引` 下面就是 `build_mapping()`）；`impl` 或函数上方的说明要么写成 `///` 让 `cargo doc` 渲染，要么删掉，别用 `//` 挂在那里。

**注释与代码不符时，先当作注释过期来查**：这类不一致本仓库清理过一批——`read_p4_lines` 的文档还在拿 fstat 举例，而 fstat 早已改走 `p4/fstat.rs` 的流式解析；`charset.rs` 的文档写 `Encoding::for_label`，代码用的却是 `for_label_no_replacement`，后者刻意拒绝「解码只能靠替换字符」的编码，语义并不相同。

**运行时输出字符串不归这一章管**：报告标题、统计行、`bail!` 文案、`rule N` 的规则描述都被测试钉着，改它们等于改行为，要单独提交并在提交信息里写明。

**只改注释的改动怎么自证**：注释不参与编译，所以「剥离注释后逐字节相同」等价于「token 流相同」。拿一段剥离注释的脚本（字符串、原始字符串、字符字面量与生命周期原样保留）把工作区文件与 `git show HEAD:<file>` 逐一比对即可。**别用「diff 里每行都以 `//` 开头」来判断**——字符串里也有 `//`（`src/workspace.rs` 的 fixture JSON 里就有），行首判断会把真实改动当成注释放过。

**改 `///` 时多跑一道 `cargo doc`**：

```powershell
$env:RUSTDOCFLAGS = "-D warnings"; cargo doc --no-deps --document-private-items
```

它不在 CI 的门禁三连里（见 [CONTRIBUTING](../../CONTRIBUTING.md)），但仓库有六十多处 intra-doc link，而 clippy 不检查它们——链接译坏了 CI 会全绿。
